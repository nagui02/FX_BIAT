1. Pourquoi le réindexage ?
Les cours BCT sont publiés uniquement les jours ouvrés tunisiens. Mais les jours fériés tunisiens (Aïd, Fête de la République...) ne sont pas fériés dans les autres pays. Résultat : quand tu feras le merge avec le Brent ou les taux Fed (qui ont des valeurs ces jours-là), tu auras des trous dans les cours BCT.
Le réindexage sur freq="B" (Business Days internationaux) remplit ces trous → l'interpolation les comble avec des valeurs cohérentes. C'est standard dans la finance quantitative.

2. Pourquoi les log-rendements ?
Trois raisons concrètes pour ton projet :
Pour GARCH (S2) : GARCH modélise la volatilité des rendements, pas des niveaux. Tu ne peux pas faire GARCH(tnd_eur) directement — tu fais GARCH(LogRet_TND_EUR).
Pour la stationnarité : Les cours de change ont une tendance (non-stationnaires). Les log-rendements sont quasi-stationnaires → nécessaire pour ARIMA.
Pour LSTM et XGBoost (S3) : Les rendements normalisent les données entre -1 et +1 approximativement → convergence plus rapide.


3. Faut-il garder les données depuis 2004 ?
Oui et non — c'est une décision de modélisation.
Pour l'entraînement des modèles (ARIMA, GARCH, LSTM, XGBoost), plus de données = mieux en général. 2004-2022 pour l'entraînement, 2023-2025 pour le test.
Mais il y a un risque : le régime de change a changé. Le TND était quasi-fixe avant 2012, puis la dépréciation a commencé vraiment après 2016. Un modèle entraîné sur 2004-2022 va "voir" trois régimes très différents. Pour ton rapport, tu peux mentionner ce point et potentiellement entraîner aussi sur 2015-2022 pour comparer.
Conseil pratique : garde 2004 pour l'instant, mais définis une variable TRAIN_START dans models.py que tu peux changer facilement.
